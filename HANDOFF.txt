================================================================================
WHAT THE PRODUCT IS
================================================================================

OVOA is a personal voice assistant with two main components:

1. JARVIS/API (Cloudflare Worker backend)
   - Hono + Zod running at https://api.ovoa.ai, on the ovoa.ai Cloudflare account
     (e58b0ec5305410f9d3cd70f461f39cb6) since the v1 move. The old address,
     jarvis-api.edgeformmedia.workers.dev, is a forwarder (jarvis/forwarder) on
     the old edgeformmedia account, which keeps only that and the old D1 as a
     backup until 2026-10-14.
   - D1 database (jarvis-db)
   - Handles chat turns, tool calling, background agent jobs
   - Interfaces with three LLM engines: DeepSeek (primary) → Gemini → Workers AI
   - Transcription proxy (Deepgram STT), TTS proxy (ElevenLabs), Google integration

2. JARVIS/APP (Expo SDK 57 iOS app)
   - React Native mobile app
   - Communicates with ES100 wrist clip over BLE
   - Controls clip button, receives audio files via BLE
   - Integrates HealthKit for health metrics
   - Development builds on Codemagic → TestFlight
   - Built and tested on real iPhone hardware only (HealthKit + ES100 require dev builds, not Expo Go)

WORKFLOW: User presses ES100 button → records on clip → presses again → app
downloads file over BLE → decodes opus → uploads to API → transcribes → model
answers → speaks back. Typical round-trip: 8–12 seconds.

================================================================================
ARCHITECTURE & DATA FLOW
================================================================================

ES100 ──BLE──> iPhone (Expo) ──HTTPS──> Cloudflare Worker
 clip          (audio decode,        (STT, model, TTS,
 mic-only      HealthKit read,       tools, DB, agent)
               chat UI)

Key architectural decisions:
- Phone owns the codec: ES100 → app decodes opus/WAV → uploads PCM16
- Backend owns the API keys: nothing shipped in app binary
- Providers sit behind interfaces: mock transcriber when keys are unset
- Standalone rule: every feature degrades gracefully without optional inputs

CRITICAL GROUND RULES (Will save you hours)
================================================================================

1. ALWAYS MIGRATE + DEPLOY after server changes
   - After any jarvis/api file changes: run in jarvis/api/, with the ovoa.ai
     account's wrangler login (wrangler.jsonc pins that account)
     export XDG_CONFIG_HOME=C:/Users/thoma/.wrangler-ovoa
     npm run db:migrate && npm run deploy
   - User expects this without being asked

2. OneDrive + git: Use git ls-files and Grep tool, never find/grep -r
   - OneDrive makes recursive file operations time out (node_modules issue)

3. Bash heredocs: Backslashes collapse inside heredocs
   - A Python/Node heredoc containing \\n becomes a real newline
   - Use Edit/Write tools instead for anything with escapes

4. TypeScript verification: Run in BOTH directories
   - jarvis/api: npx tsc --noEmit
   - jarvis/app: npx tsc --noEmit

5. Test the server without Cloudflare auth
   - npx wrangler dev --local --port 8787 --var DEBUG_KEY:localtest
   - Then: npm run smoke (47 checks, needs no auth)

6. Read phone logs before guessing
   - Device logs live in D1 device_logs table, uploaded every 3 seconds
   - Query: npx wrangler d1 execute jarvis-db --remote --json --command
     "SELECT time, kind, text, detail FROM device_logs ORDER BY id DESC LIMIT 200"
   - Check this FIRST when debugging app-side issues

7. Hardware requirements
   - HealthKit and ES100 BLE module need development builds (Codemagic → TestFlight)
   - Expo Go cannot test HealthKit, BLE, or ES100 features
   - Always test on real iPhone, never in simulator for hardware features

8. ES100 clip constraints
   - Motion stream is ~1 Hz gyro only (twist-to-listen dropped due to this)
   - Motion commands flood freeze the clip (don't send them rapidly)
   - Keep ≥30 seconds between buzzes (queue duplicates if closer)
   - SDK status 0 means "Connected" by default (use bridge's linked flag)

9. Expo documentation: Read before writing Expo code
   - https://docs.expo.dev/versions/v57.0.0/
   - Expo has changed; don't write from memory
